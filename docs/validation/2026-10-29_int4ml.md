Observaciones menores:

- ⚠️ **1.a. p bilateral dentro de Holm.** `p_bloques` es bilateral y se calcula también cuando ΔAUC < 0 (M-L2|T2: 0,007,
  significativamente *peor*). En el procedimiento escalonado de Holm, ese p pequeño "en la dirección contraria" ocupa el
  primer escalón y relaja el umbral de los demás (α/3 en vez de α/4). Es heredado de INT-4 y el criterio (i) exige además
  ΔAUC > 0, así que no puede declarar establecido un empeoramiento; pero es anticonservador para los otros tres. Aquí no
  importa: el siguiente p más pequeño es 0,236 (M-GB|T1), lejos de cualquier umbral. Diff propuesto (para futuros usos,
  no para reabrir este resultado):

  ```diff
  -    h_i = I3.holm({k: v["estratificada"]["p_bloques"] for k, v in C.items()})
  +    # unilateral en la dirección de mejora: un empeoramiento significativo no debe abrir escalones de Holm
  +    h_i = I3.holm({k: (v["estratificada"]["p_bloques"] / 2 if v["estratificada"]["d_auc"] > 0 else 1.0)
  +                   for k, v in C.items()})
  ```
  (o, equivalentemente, pasar a Holm `1.0` cuando ΔAUC ≤ 0, conservando el p bilateral).

- ⚠️ **1.b. Temporal con AUC estratificada.** El prerregistro no fija la métrica del criterio (iv); el código la concreta
  como estratificada antes de correr (docstring de 34858ee). Con la agrupada el signo es el mismo en los 4 contrastes
  (M-L2|T1 −0,019, M-GB|T1 −0,026, M-L2|T2 −0,299, M-GB|T2 +0,064). Sin efecto.

- ⚠️ **1.c. Sin test que compare las filas con INT-4.** No hay test que lo afirme, pero el JSON reproduce exactamente las
  filas, eventos y AUC del logit de `int4_resultado.json` / `int4_sensibilidad_liston.json` (T1 1090/166, 0,7319; T2
  235/163, 0,7703). Comprobado a mano.

**Veredicto del punto 1: ✅** — lo corrido coincide con lo congelado; las concreciones son razonables y están fijadas antes
de correr.
